# Screenshot gallery

The README images are captures of the actual Expo Router interface and real Phaser/Three.js runtimes. They are generated by `tests/screenshots/gallery.spec.ts` using `playwright.screenshots.config.ts`.

## Reproduce

```sh
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
pnpm screenshots
# If the default port is occupied:
SCREENSHOT_UI_PORT=8395 pnpm screenshots
```

No database, native simulator, funded provider key or real account is required. The command exports the mobile UI into ignored `work/`, starts a loopback preview, writes PNGs under `docs/images/` and stops the preview afterward. Linux may need `playwright install --with-deps chromium`.

UI captures use a 430×932 viewport at 2× pixel density. They use a synthetic `demo@example.com` identity, demo profile, internal credit balance and generation/library data. All remote requests are fulfilled locally or blocked; analytics and symbol uploads are disabled. The harness never reads production mobile configuration. Generation stages, a completed library entry and a resumable error are demonstration states, not claimed live AI output.

Gameplay captures unpack and verify the committed Neon Comet package, or build/sign the explicitly deterministic 3D/isometric fixture with a fresh in-memory test key. Chromium loads the files with networking disabled and communicates with the real scoped application bridge. The captures show the actual game canvas after gameplay starts. They are browser-runtime evidence, not native WebView or device-attestation verification.
