# Deployment and distribution

Deploy this project to infrastructure you control. No public backend, project key or operator account is bundled. Prepare independent private server and public mobile configuration using [ENVIRONMENTS.md](ENVIRONMENTS.md). Missing production configuration fails before startup.

Production templates enable spending limits, rate limits and app verification. Configure Apple/Google verification, anonymous Auth, signed native identities and the [integrity migrations](APP_INTEGRITY.md) before exposing services. Validate paid generation and physical devices separately.

1. Provision a production Supabase project/Postgres database. Apply the SQL migrations using a privileged migration role; assign a dedicated API/worker role with only necessary access. Local postgres superuser settings are development defaults. Configure verified email, SMTP, redirect allowlists, signup abuse controls and backup retention.
2. Run the trusted API and worker on separate managed processes with Node/pnpm, pinned dependencies, TLS ingress and private DB access. Keep artifact storage durable/shared and private. LocalStorage is the implemented storage adapter; an object-storage adapter is a future scaling change, not silently configured here.
3. Build `ai-games-sandbox:1` using the supplied Dockerfile. Run the worker with access to a **dedicated** Docker daemon and installed Playwright Chromium/dependencies. Do not expose the Docker socket to agents or share this daemon with unrelated production workloads. Restrict host gateway 4101 to the Docker/worker network. Public ingress should expose only the API over HTTPS.
4. Generate a production Ed25519 pair. Store the private PEM only on the worker using secret management, and embed raw public hex in the mobile build. Give API artifact read/delete access; never expose artifact filesystem paths publicly. Back up DB and artifacts together. Rotate OpenRouter key and signing key deliberately.
5. Configure a funded, limited OpenRouter key and available text/tools coding model and priced per-image model. Review defaults and cost telemetry. Run `test:generation:live` with a running worker; it must create and modify genuine gameplay, not just a fixture. Test cancellation, failed/oversized output and insufficient provider credits.
6. Point mobile public environment variables at production HTTPS URLs, configure PKCE email confirmation/recovery redirects, then run native builds. `apps/mobile/eas.json` defines development/internal/production profiles. Link the Expo project and provide Apple developer/signing and Google Play signing/service-account credentials through the build provider. Those credentials and accounts were not supplied here.
7. Use an owned HTTPS sharing domain, verified iOS associated domains and Android App Links, and a web fallback for devices without the app. Current invitations use the `aigames://share/<token>` production scheme (`aigames-dev://` in development). Universal-link hosting/configuration is a remaining production integration; do not claim it works yet.
8. Publish a hosted privacy policy and support/contact destination, staff report review/takedown, assign store content/age ratings and exercise accessible controls on physical devices. Current privacy copy and 16+ self-attestation are development foundations, not legal/store certification.

## Budgets and abuse controls

Keep the [protective switches](ENVIRONMENTS.md#protective-defaults-and-budgets) enabled. Review per-job and global daily caps, user quotas and provider-side budgets before funding a key. Existing private configurations retain explicit values, so audit older deployments for disabled switches. Restart API and worker together after changing policy; no mobile build is needed for server-only quota switches. Actual provider usage is always retained.

## Crash recovery and maintenance

Apply `202610120001_generation_checkpoints.sql` and `202610120002_checkpoint_worker_access.sql` with the table owner or a superuser. Production's trusted `ai_games_app` role needs explicit checkpoint table and call identity sequence privileges even with `BYPASSRLS`; the second migration grants them and checks that they were applied. Keep checkpoint tables inaccessible to `anon` and `authenticated`. After deployment, verify authenticated `/generations` as well as `/health`, and exercise checkpoint insert/update and retry in a rolled-back, unbilled database transaction using the actual API/worker role. A health response alone does not verify database permissions. Rebuild `ai-games-sandbox:1` when adopting checkpoint support so the CLI can preserve and resume its native session.

Normal cancellation/timeout closes sandboxes and grants. An abrupt worker/host crash can leave `aig-gen-*` containers and internal networks. Inspect the corresponding `generation_jobs` and pg-boss jobs before deleting anything; never remove an active worker's sandbox. Mark abandoned jobs failed and remove their exact containers/network. Restore/restart the worker after reconciling reserved spending with provider invoices. The worker automatically reconciles jobs with no stage change for at least 30 minutes on startup and each minute, marks them failed and removes the exact containers/network. Adjust grace above twice the configured job timeout. Maintenance still needs operational monitoring.

Schedule orphan artifact cleanup by comparing version artifact/source keys against the private artifact root. Include unpublished failed-job outputs and interrupted account deletions. Deleting selected local downloads leaves older version folders; production storage housekeeping should enumerate tracked versions and account directories. Preserve snapshots/backups according to the announced deletion policy. Avoid deleting unrelated Docker data or user files.

## Store policy caveats

Downloaded game JavaScript, mini-game catalogs, user-created content and native bridges require review against current platform rules. The player restricts native capabilities and supports reporting/blocking/account deletion, but review approval is not guaranteed. Before submission, verify Apple [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/) especially section 4.7 and Google Play's current content/dynamic-code policies. Missing verified HTTPS links, report-review operations and live-generation proof are release blockers. No store submission or signed device distribution has been performed.
