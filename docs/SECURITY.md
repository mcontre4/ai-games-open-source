# Security

## Boundaries

Games and AI-created source are untrusted. The native host alone owns authentication, database access, installation and sharing. Game packages receive no JWT, API key, service-role credential, native file path, camera, microphone, location or payments API. GameSDK returns only a display name, game metadata and scoped progress. External requests/frames/workers/forms are blocked by CSP; Android additionally returns 403 for every resource outside the exact game origin/path. iOS permits main navigation only to the installed entry, scopes file reads to the package directory, and disables universal/file URL access, cookies and DOM storage.

Bridge messages have strict discriminated schemas, 70 KiB encoded limit, bounded state depth/64 KiB size, capability checks, request correlation/deduplication and 30 requests/second. Saves/scores cannot supply account/game identities. Scores are validated but **not cheat-proof**: offline clients control gameplay, so leaderboards are casual rather than competitive/financial.

ZIP central-directory checks run before decompression, rejecting traversal, absolute paths, duplicates, symlinks, encryption, unsupported methods, overlapping ranges, excessive entries/size/ratio and unlisted files. The package verifier authenticates the pinned Ed25519 key and every asset. Signed versions are immutable. The private signing key is never embedded in mobile, game or agent. Key rotation currently requires a new app build and explicit re-signing/version publication; no silent trust of a package-supplied key.

Codex CLI has one configured provider: the controlled OpenRouter gateway. Agents get only an expiring per-job grant. The trusted worker invokes the CLI through Docker exec; no agent HTTP control port is published. Agent containers are non-root, read-only, capability-free, no-new-privileges, memory/CPU/PID bounded, tmpfs only, without host mounts or Docker sockets, on an internal network. A trusted relay connects that network to the one controlled inference endpoint; the relay forwards only the controlled inference paths. Agents cannot browse/download/install/execute shell commands via tools. Codex runs with read-only built-in permissions and shell/web tools disabled. The gateway advertises only the scoped game-files MCP read/write tools and rejects other returned tool calls. That server allows reads from a fixed starter-file list and writes only to Game.ts and game.json, rejects symlinks and bounds writes. Only trusted build commands execute frozen dependencies. Files outside the allowed gameplay/assets/metadata set fail validation. Chromium runs on the trusted validation host and must be isolated appropriately in production; static analysis is defense in depth, not a proof that arbitrary JavaScript is harmless.

## Spending and abuse

Production requests require Apple App Attest or Google Play Integrity verification bound to the session, method, path, body and a single-use challenge. Private downloads additionally enforce game/version access. Anonymous identities generate under the same quotas and credits; a secret guest credential authorizes atomic account linking without resetting usage. Old guest sessions and RLS access are revoked. See [APP_INTEGRITY.md](APP_INTEGRITY.md) for configuration and physical-device requirements. Authorized players can still copy downloaded content.

API rate limits, prompt shape validation, age attestation and ownership checks run before jobs. The application generation use case requires a typed moderation assessment before art direction, images, gateway grants, sandboxes or publication. The trusted worker uses pinned `typesafe/jev-1.13` through OpenRouter's Decisions API; the key never reaches games or sandboxes. Independent Noul questions cover explicit sexual content, child exploitation, extreme violence, hate/harassment, self-harm, real-world illegal assistance, real-money transactions, external connections, security abuse and non-games. Ordinary combat, nonsexual romance, fictional currency, local simulations and app-provided GameSDK capabilities are allowed. Context and negation are assessed by Jev rather than a keyword blacklist.

The domain rejects any prohibited probability >= 0.7 with fixed category-specific messages. Probabilities from 0.3 to below 0.7 require a clearer prompt and also stop generation. Malformed/missing/out-of-range answers, provider errors, unknown models and timeouts fail closed. These initial conservative thresholds need ongoing calibration against reviewed prompts; model classification is not a security boundary or a guarantee of perfect detection. Runtime CSP, restricted SDK/bridge capabilities and generated-source checks independently enforce containment. Games cannot handle real payments; only the host app can expose billing. A rejected queued job becomes `failed` with its explanation visible through the existing generation UI; it consumes the normal daily request quota and only the classifier's actual inference cost.

Jev requests have a 24 KB payload cap, a 30-second deadline linked to job cancellation, a TypeSafe-only route and no provider fallback. Endpoint discovery requires active decision endpoints with bounded positive input pricing and zero output pricing. Inference is reserved before calling Jev and settled before interpreting its answers. Uncertain failures retain their reservations. Age 16+ self-attestation is checked for create/modify. Advisory locks atomically enforce per-user concurrent/day limits and global UTC daily cost reservations. Each inference reserves a conservative maximum before the request; upstream model, provider fallback, max output and streaming are controlled. Image discovery admits only priced per-image endpoints. Actual costs are recorded; unexpected price overruns fail the job and need operator investigation. Configure an **OpenRouter account/key spending limit as an independent backstop**. Provider billing/pricing changes can exceed an estimate; application reservations do not guarantee a provider's final bill.

Account quotas do not establish unique humans. Production needs email verification, Auth signup/CAPTCHA/rate controls and an abuse response policy. Generation reports and creator blocking work; a production operator still needs staffed report review/takedown procedures. No public moderation dashboard is included.

## Operations and limitations

Local published Supabase ports bind loopback. Production requires TLS, network isolation, a dedicated worker/Docker host and least-privilege DB roles instead of the local postgres superuser. The worker is trusted to control Docker; do not share its daemon with unrelated workloads. The host gateway currently listens on 0.0.0.0 so the Docker relay can reach it; **firewall 4101 to the worker/Docker network**. It requires a random grant and exposes no raw credential, but should not be internet/LAN-public.

Cancellation polls active jobs and aborts model calls; cleanup is finally-based. A startup/minute janitor marks jobs with no stage change for at least 30 minutes failed and removes their exact containers/networks. While the entire worker fleet is down, reconciliation waits until restart. Backups require encrypted retention/access policy. Account deletion cascades database records and deletes owned artifact directories and account-local installations; copies already downloaded by friends remain offline, as disclosed. Root artifacts left by exceptional interrupted deletion or unpublished failed jobs require scheduled orphan cleanup.

No credentials are logged. API errors are redacted, provider errors are reduced, and prompts are not emitted in routine logs. Security tests exercise hostile archives, forged tokens, RLS, ownership, saves, bridge abuse, AST restrictions and actual container egress/write denial. Production penetration testing and real-device abuse testing remain necessary.
