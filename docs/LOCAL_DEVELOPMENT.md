# Local development

Select local services with `pnpm dev` and your own configured production services with `pnpm prod`. See [environment separation](ENVIRONMENTS.md) for configuration precedence, native variants and production commands.

Run the README commands in order. `dev:infra` starts local Supabase with unused studio/functions/analytics components excluded. It rebinds published project database, Auth/API gateway and test mail ports to **127.0.0.1** through the Docker API, including on Docker Desktop, where network-level default binding options are insufficient. Existing volumes are preserved. Only this project's labelled containers are changed. `pnpm stop:infra` stops them without deleting data.

`setup:local` preserves an existing AI key, refreshes local project credentials and writes only public variables to `apps/mobile/.env.development`. Keep `.env.development`, `work/keys/private.pem`, artifacts and native build caches out of Git. Regenerate and reseed a fresh clone before building the sample; the committed sample is verified by its own bundled public key, while server downloads use the app's configured public key.

Paste your funded **OpenRouter** API key after `OPENROUTER_API_KEY=` in the repository-root `.env.development`, then restart `pnpm dev:api` and `pnpm dev:worker`. A ChatGPT subscription does not supply this key. The configured coding model is [GPT-6.1 Sol](https://openrouter.ai/openai/gpt-6.1-sol) with [high reasoning](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens); the image model is [Muse Image](https://openrouter.ai/meta/muse-image). Codex tool calls use OpenRouter’s native [Responses API](https://developers.openai.com/api/docs/models/gpt-6.1-sol). The $100 daily cap includes coding, moderation and images. The separate $10 per-generation cap and account quotas still apply. Each modification is a separate generation with its own $10 cap. Configure an independent spending limit on your OpenRouter key as well.

An Android emulator maps loopback API/Auth URLs to `10.0.2.2`. Physical devices require reachable HTTPS API/Auth URLs; localhost is the device itself. Email recovery/confirmation use PKCE and `aigames-dev://auth` / `aigames-dev://recovery`; configure these in Supabase redirect allowlists. Local email confirmation is disabled for test signup; test mail UI is http://127.0.0.1:54324.

Expo Go cannot include the custom Android offline module. Use a custom development client or Release build. `pnpm --filter @ai-games/mobile exec expo run:ios --configuration Release --device 'iPhone 16' --no-bundler` embeds the JavaScript bundle. Android: prebuild, then `gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a`. Change architectures for the desired devices. Native folders are generated and ignored; the custom Expo module is tracked under `apps/mobile/modules/offline-game`.

Browser export previews the app interface. The web player intentionally explains that native offline gameplay requires iOS/Android; it is not a native security or file-loading test.

For an already installed iOS development client, `pnpm dev:ios` starts Metro at localhost:8084 and opens the simulator. Keep Metro running during development. Native downloads resolve their account/version directories against the current app document directory, so an iOS update that moves the data container does not leave existing games pointing at an obsolete absolute path. Local saves remain in SQLite.

The SDK 54 app uses the tracked `with-ios-scene-lifecycle` config plugin when generating iOS projects. Xcode 27 / iOS 27 requires a scene lifecycle: AppDelegate initializes Expo, and SceneDelegate creates the scene's window and starts React Native. Scene callbacks forward incoming links and lifecycle events to AppDelegate. Keep this integration in the plugin rather than editing generated native files; review and remove it when upgrading to an Expo version with built-in scene support. A successful device launch command alone does not prove startup works—confirm the app remains open and renders its interface.

Game coding runs with `@openai/codex@0.162.1` installed in the Docker sandbox image. Rebuild with `pnpm sandbox:build` and restart the worker after upgrading the agent. No host Codex installation, ChatGPT login or OpenAI API key is needed. Codex uses a custom Responses provider pointed at the controlled gateway, which forwards native Responses requests through OpenRouter with bounded spending and only scoped file tools. Moderation, art direction and image generation continue through OpenRouter. Generation and repair use fresh ephemeral CLI turns over the current workspace; modification starts from the saved immutable source archive.

The pinned CLI uses a sandbox-local model catalog derived from [OpenAI’s `rust-v0.162.1` metadata](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/models-manager/models.json). It selects ordinary Responses and direct MCP tools instead of Sol’s bundled ChatGPT-only Responses Lite/Code Mode profile. The gateway independently pins the actual OpenRouter model and high reasoning effort; only game file read/write tools are exposed.

Muse requires the OpenRouter account owner to confirm 18+ eligibility at [account preferences](https://openrouter.ai/settings/preferences). Missing confirmation produces a 403 with `missing_attestation_types: ["age_18plus"]`; confirmation can take time to reach the API. Muse can also have an empty Image API endpoint list despite being available for generation. In that case, the adapter discovers the same Muse model through `/models/meta/muse-image/endpoints`, pins its active provider and reserves the advertised full context/output token ceiling at the prompt, completion and image-output rates, with a 50% margin. Generation still uses `/images`; there is no alternate-model or fixture substitution. Premium requests target 2K and the requested orientation, and delivered assets must pass the pixel-size check. Muse's general catalog does not advertise exact dimension capabilities, so delivered aspect ratios can differ from the request.

Coding Responses use a 400 KB normalized context limit (500 KB inbound transport limit) to include bounded opaque reasoning/file-write history. Chat art direction retains its 100 KB limit. Jev moderation uses a separate 24 KB Decisions request with ten typed Noul questions and a 30-second ceiling. It does not require coding tools or reasoning options. Every normalized request reserves its byte-based worst-case prompt cost plus any configured reasoning/output allowance before paid inference. Coding requests use the remaining grant deadline, abort on CLI disconnection, and have a ten-minute provider ceiling.

`pnpm test:moderation:live` evaluates 22 labeled prompts against real Jev with a $0.05 total reservation. It needs local Supabase/Postgres and a funded server key. It creates a temporary evaluation ledger without a generation outbox entry, so it cannot dispatch artwork or game coding; its test user and ledger are removed afterward. Results and actual cost are retained under ignored `work/jev-live/`. This is live prompt-classifier evidence only, not full live game generation. The adapter uses the documented [Jev Decisions API](https://openrouter.ai/docs/api/api-reference/alphadecisions/submit-a-decisions-request).
