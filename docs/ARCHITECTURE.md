# Architecture

Domain → no infrastructure. Application owns ports and use cases. Adapters implement ports; API/worker/mobile composition inject concrete services. Presentation coordinates these services and renders state. `scripts/check-boundaries.ts` checks imports, and ESLint disallows common unsafe practices. Time and identities are injected into use cases; server identity uses cryptographic random values.

| Location                 | Responsibility                                                                                             |
| ------------------------ | ---------------------------------------------------------------------------------------------------------- |
| `apps/mobile`            | Expo Router screens; authenticated host; SQLite/native installer/player adapters                           |
| `apps/api`               | Fastify HTTP delivery and authenticated user context                                                       |
| `apps/worker`            | pg-boss generation consumer and trusted AI service composition                                             |
| `packages/domain`        | Pure entities, ownership, prompt/save/score rules                                                          |
| `packages/application`   | Single-execute game/share/save/generation/bridge/sync use cases and ports                                  |
| `packages/contracts`     | Strict Zod HTTP, manifest and bridge schemas                                                               |
| `packages/adapters`      | Postgres, Supabase Auth, local artifact storage, OpenRouter/Codex CLI, Docker, signing, browser validation |
| `packages/game-sdk`      | Restricted game bridge client, package preflight/signature verification                                    |
| `packages/game-template` | Versioned Phaser runtime and visibly separate Neon Comet fixture                                           |
| `packages/config`        | Validated environment and bounded operational settings                                                     |
| `packages/ui`            | Shared design tokens/motion; native components live in mobile presentation                                 |
| `infrastructure`         | SQL/RLS, local Supabase, controlled sandbox image/relay                                                    |

Create reserves user quotas/global spending and writes game, job, event and persistent outbox in one transaction. pg-boss dispatch uses a deterministic job UUID, making outbox retry idempotent. The worker moderates the prompt and produces a strict per-game art direction from the user's theme/style requests, inferring missing choices. The same direction controls image generation, gameplay instructions and metadata-driven menu/HUD colors, typography and corners. Modifications supply previous version metadata so gameplay changes preserve the existing style.

Prompt shape validation and the allow/reject/clarify probability policy are pure domain rules. The application owns `ModerationPort` and `GenerateGame.execute` requires its typed assessment before invoking any generation services. `JevPromptModeration` is an outbound adapter that validates provider answers and maps them to domain evidence. Worker composition injects that adapter; deterministic test assessments live only in explicitly named test fixtures. The API queues authenticated requests after shape, quota and ownership checks; model rejection is persisted as a failed job with a fixed explanation. This keeps paid classification inside the reserved job budget and preserves existing playable versions on rejected modifications.

The persisted game view selects a frozen Phaser 2D or Three.js 3D/isometric starter; the same view informs art direction and is signed in the package. Modifications retain it. The trusted 3D host owns renderer/camera, resize, frame timing and local artwork loading. See [GAME_VIEWS.md](GAME_VIEWS.md).

The worker creates a unique restricted container/network, requests artwork at the game's aspect ratio (2K for premium quality), then uses the official Codex CLI to edit gameplay and metadata. The production starter has no Neon Comet art or branded interface. Build configuration, dependencies, SDK and boot files are frozen; the safe theme schema supplies presentation values. Binary artwork/source transfers use bounded stdin/export helpers inside the existing unprivileged container, avoiding Docker Desktop archive handling of tmpfs without host mounts or added permissions. The trusted host scans generated source, checks rendering/controls/frame cadence in Chromium, signs a manifest and uploads immutable package/source archives. Only then does a transaction publish the version and mark the job ready. Validation can invoke at most the configured repair count while retaining the original prompt and art direction. Finally cleanup destroys the sandbox/network and revokes the grant.

Modify starts from the current source archive, produces a new immutable version, preserves prior versions and uses state schema 1. Switching versions is a download operation. Future incompatible schema migrations must be explicit; the player declines incompatible saved state instead of guessing.

Download checks whole-ZIP SHA-256, Ed25519 manifest, asset hashes/lengths, ZIP limits/paths and capability/platform compatibility before extraction. Files are staged in the account's document directory, then atomically moved and registered in SQLite. A failed installation never becomes playable. iOS scopes WKWebView read access to that directory. Android serves only those files through WebViewAssetLoader at a unique HTTPS origin, with no arbitrary file access or network fallback.

GameSDK requests carry protocol/correlation/type only. The authenticated host supplies account and manifest context; the game cannot choose a user or another game. Writes land in SQLite first. Foreground/background/reconnect sync pushes with the cloud base revision. The server serializes saves and rejects stale revisions. Conflicts retain the local copy and restore the newer cloud value; settings allows an explicit local-copy restoration. In-flight local writes remain dirty after acknowledgements. Each request is pinned to its initiating account. Leaderboard high scores are per player and take the maximum.

Private games are visible only to owners and accepted share members. Invitations are random, stored hashed, expire, and can be revoked. Downloads and online access check ownership/membership/blocking; an already installed offline copy cannot be remotely erased. RLS independently limits direct authenticated database reads, and sensitive writes are revoked from public client roles.

## Saved generation progress and retries

Generation checkpoints are private server data. The worker retains the approved moderation decision and art direction, original generated artwork, editable source, native Codex CLI session/rollout history, tool events, validation diagnostics and paid provider request/response bodies. Provider bodies are saved before cost settlement; Authorization headers and configuration files are excluded. Fresh scoped gateway grants are issued on every sandbox restore. Conversation data never enters a downloadable game package or the public generation response.

Checkpoints are written before each coding request, after every successful game-file write, after stage output, every 30 seconds during coding and before cleanup after failure. Source/context archives and artwork use immutable keys under the owning game's private artifact folder; the database atomically references the latest complete snapshot. If saving fails, the worker leaves the surviving sandbox for operational recovery. A worker lease prevents concurrent execution of the same job. Restart/maintenance recovery exports a surviving interrupted container before removing it. An abrupt host/container loss can discard a write that had not yet acknowledged its checkpoint; all acknowledged writes and previously stored provider responses remain durable. Back up the database and artifact root together.

Temporary provider errors, interrupted CLI turns and attempt timeouts receive at most three attempts per queued job. The attempt counter survives worker restarts. Art and successful coding stages are reused; build/validation still run before publishing. Definite unbilled HTTP rejections release their exact reservation. Ambiguous transport failures retain unresolved reservations and block more inference until the provider bill is reconciled; they are never assumed free.

After a terminal failure, the app offers **Resume creation** when saved state exists, or **Retry creation** for a legacy/pre-work failure. `POST /generations/:id/retry` creates one owner-authorized successor attempt for the same game/prompt/base version, inherits the checkpoint, resets its automatic-attempt counter and enqueues it atomically. Duplicate concurrent requests return that same successor. Only failed jobs can be resumed. Actual spending remains on the original job; the successor uses the current day's credit policy and remaining cumulative creation budget. Existing concurrency, quota and spending switches still apply. Unresolved bills block manual retry as well. Saved progress does not replenish OpenRouter funding, and failures from before checkpoints were introduced cannot recover already destroyed workspaces.

Deploy migration `202610120001_generation_checkpoints.sql`, rebuild `ai-games-sandbox:1`, and restart API/worker before using this feature. The mobile status screen change also requires shipping/reloading the updated client. Retain all referenced checkpoint archives and provider call rows; game/account deletion removes their private state. Old unreferenced snapshot archives can be garbage-collected only after checking inherited retry references.
